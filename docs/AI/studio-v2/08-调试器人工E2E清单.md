# 08. 调试器人工 E2E 清单

> 状态：2026-08-17 对照当前代码回写（挂机 UX / MemoryCommit Trace）。  
> 目标：验证 Studio V2 调试器电话壳 UX、LLM FC、挂机记忆抽取、留言、外呼调度链路。本文不是产品验收签字，只是人工走测脚本。

## 1. 提交前核对

提交代码前先看 `git status --short`，按下列口径处理：

| 类别 | 建议 |
|------|------|
| `apps/studioV2/**`、`packages/rpg-engine/**`、`package-lock.json` | 本轮功能代码与测试，原则上应提交 |
| `data/storis-packages/**`、`data/characters/**`、`data/assets/**` | 若是示例内容或资源能力改动，应提交 |
| `data/users/demo-user/profile.save.json` | 人工调试会污染，提交前必须单独确认是否真要更新示例档 |
| `data/logs/`、`data/debug-dto/`、`data/memory/*.sqlite` | 运行时产物，不提交 |
| `.env.local` / `AIRPC_LLM_API_KEY` | 本机密钥，不提交 |

提交前建议命令：

```bash
git status --short
npm run quality:engine
npm run quality:studio
```

## 2. 启动前准备

1. 确认 `.env.local` 或当前 shell 环境里有 `AIRPC_LLM_API_KEY`。
2. 启动 Studio V2。
3. 用默认调试用户 `demo-user` 走测；如果改用户，失败信息里记录 userId。
4. 打开浏览器控制台，保持 Network 面板可用。

## 3. 外部调试器入口

入口：`/debugger`

验收点：

1. 初始状态：号码盘、重播、挂断不可用；摘机、免提可用。
2. 点击摘机或免提后，号码盘、重播、挂断放开；摘机和免提禁用。
3. 连续输入号码时不会立刻锁键；停止输入约 2 秒后进入“拨号中”遮罩。
4. 拨到有 free card 的角色时进入通话界面；玩家主动呼入 unknown caller 首句应像真实接电话，期望类似「喂，请问哪位？」。
5. free card 首句不应出现 Story 专属剧情话术，例如“打错电话”“既然接通就不算错”等。
6. unknown inbound 首句不应直呼当前用户姓名/昵称，也不应提历史记忆或上一通对话。
7. 拨到没有 free card 或不可拨角色时，不进入剧情卡；记录实际 UI 提示。

失败时记录：

- 输入号码。
- Network 中 `/api/debug/call/start` 的响应。
- `data/logs/debugger/` 和 `data/logs/llm/` 当日文件是否有新行。

## 4. 编辑器章节入口

入口：从故事编辑器顶部进入调试器。

验收点：

1. 调试器不开放手选故事包/章节。
2. 进入后应按当前章节入口章启动，而不是让用户再选。
3. 通话界面显示当前角色、聊天区、右侧当前卡调试信息。
4. LLM 首句与当前通话卡 prompt / objective 基本对得上。

失败时记录：

- 编辑器 URL。
- 跳转后的 debugger URL。
- `/api/debug/call/start` 请求体与响应。

## 5. LLM FC 能力

在通话中自然引导 LLM 使用工具：

| 能力 | 人工话术例子 | 期待 |
|------|--------------|------|
| 记住名字 | “我叫小陈，你以后这么叫我。” | 工具调用成功，后续对话能使用名字 |
| 搜索记忆 | “你还记得我叫什么吗？” | 若前一步成功，应能查到 |
| 约定外呼 | “两分钟后再打给我。” | 挂机后产生 schedule / incoming 链路 |
| 角色主动挂机 | “那你先忙吧。” | LLM 可触发 `request_hangup`；立刻回主界面；toast「对方已挂断」；若有挂机后副作用则出现不可关闭 overlay |

失败时记录：

- 对话文本。
- UI 右侧最近工具调用。
- `data/debug-dto/tool-calls/` 对应 DTO。
- `data/logs/tools/` 和 `data/logs/shell/` 当日文件。

## 5.1 挂机记忆抽取

打一通有实质对话的 free call（用户说出可记忆事实，例如名字、近况），再挂断。

验收点：

1. 用户点挂断：立刻回待机主界面，toast **「您已挂断」**。
2. 出现不可手动关闭的全屏副作用面板；执行完自动关；行内容同步浏览器 console。
3. 面板可见 Memory Trace：policy、committed/skipped、entry 数量、`dtoId`。
4. `data/debug-dto/memory-commits/` 出现对应 session JSON；含 LLM 输入、raw 输出、过滤计数、写入结果。
5. 至少有一条 `call_summary`；用户事实进 semantic，不得把 NPC 自述/命理工具结果写成 userFacts。
6. 下一通普通对话（非 unknown inbound 首句）应能在热层或 `search_memory` 里见到本通摘要。

失败时记录：

- overlay / console 的 Memory Trace 行。
- `data/debug-dto/memory-commits/` 对应文件。
- `data/logs/llm/` 是否有 `memory_commit.extracted`。
- SQLite 中该 `call_id` 的 layer/kind。

## 5.2 聊天流 SSE 体验

发送玩家文本后，Network 应命中 `POST /api/debug/call/message/stream`（`text/event-stream`）。

验收点：

1. 点击发送后立即出现用户气泡；输入框清空但用户消息不消失。
2. NPC 消息先显示“思考中”，思考内容完成后收折，展开仍保留思考结果。
3. 正文按 token 流式出现；换行、列表、Markdown 在流式中不出现明显断层。
4. 工具调用出现轻量卡片，展示 toolId / round / 成功失败与参数、结果预览。
5. 输出过程中自动吸底；用户向上滚动会暂停跟随，出现“回到底部”提示；点击后恢复跟随。
6. 输入框 Enter 发送、Shift+Enter 换行；回复中按钮变为“中断”，点击后不显示错误，保留已输出内容。
7. 失败时消息流末尾出现可重试块；重试复用最后一条用户消息。
8. 长会话超过 50 条后仍能正常滚动，不卡死。

失败时记录：

- `POST /api/debug/call/message/stream` 的响应头与事件流。
- 浏览器 Network 中是否收到 `message_start / thinking_* / text_delta / tool_* / session_snapshot / done`。
- 断开或中断后的 UI 表现是否保留了半条回复和用户消息。

## 6. 真实外呼调度

推荐先用“约定外呼”自然触发，也可以用 E2E seed API 造种子。

验收点：

1. 当前无通话时，到点后出现来电 modal。
2. modal 显示角色名、头像、接听、挂断。
3. 点击挂断只关闭 modal，不开始通话。
4. 点击接听进入该角色外呼通话，LLM 先发言。
5. 预约/计划回电开场应带回电话题或合理承接，不应退化成 free inbound 的「请问哪位」。
6. 当前正在通话时，pending 外呼不弹 modal；当前通话结束后再刷新/轮询可看到 pending 外呼。

失败时记录：

- 约定外呼的原始对话。
- `data/debug-dto/schedule-intents/` 是否有对应文件。
- `data/logs/schedule/` 是否有 `schedule.clock_pump.advanced`。
- `data/logs/debugger/` 是否有 incoming accepted/rejected。

## 6.1 Opening / Prompt Trace 核对

在右侧 Prompt Trace 面板核对：

| 场景 | 期待 |
|------|------|
| 玩家主动拨入 free card | `firstTurnMode=direct`；`callerVisibility=unknown`；`includeMemory=false`；`includeInertia=false` |
| 预约/计划外呼 | 显示 scheduled callback / outbound 相关 provider 或 hard block；首句可走 LLM opening |
| 深夜/清晨玩家呼入 | 可轻微体现时段；仍不得识别用户身份 |
| 重复刷新/重拉 session | 首句不重复出现；重复消费应保持单条 assistant opening |

失败时记录：

- Prompt Trace 的 openingSituation 摘要。
- `firstTurnMode` / `firstTurnStatus` / `callerVisibility`。
- `data/debug-dto/call-sessions/` 对应 session 快照。

## 7. 留言灯与留言

验收点：

1. 有未读留言时，待机界面留言灯闪烁。
2. 摘机或免提后提示“有新的留言，点击 * 号可看留言”。
3. 点击 `*` 后弹出确认框，展示角色和留言信息。
4. 点击确定后，留言状态按当前设计更新；再次查看不应重复当作新留言。

失败时记录：

- mailbox API 响应。
- `data/debug-dto/shell-events/` 或 mailbox 相关 DTO。
- UI 上是否只是灯不亮、提示不出现，还是确认框内容不对。

## 8. 最后通过标准

人工 E2E 可认为第一版可用，需要同时满足：

1. 外部入口能 free call。
2. 编辑器入口能进入章节调试。
3. LLM 能正常首句、对话、至少一次业务 FC 成功。
4. 角色主动挂机能被 UI 正确消费（toast「对方已挂断」+ 副作用 overlay）。
5. 挂机后 MemoryCommit 至少写出 call_summary；Memory Trace DTO 可回查。
6. 约定外呼能落 schedule，并在待机时弹真实来电 modal。
7. 通话中外呼不打断当前通话。
8. 留言灯和 `*` 键查看留言可用。

任何一项失败，保留现场，不要清空 `data/logs/` 和 `data/debug-dto/`；把失败步骤、时间点、角色、userId 发给 AI 反查。
