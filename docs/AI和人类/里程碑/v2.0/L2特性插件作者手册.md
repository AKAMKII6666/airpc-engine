# 特性插件作者手册（L2）

面向**第三方 / 伙伴**：如何为 Studio V2（及未来同契约壳）编写、安装、调试一个特性插件。

| 关联 | 路径 |
|------|------|
| 工程定稿 | [技术设计 25 · L2](../../技术设计文档/25-L2第三方能力包与SDK.md) |
| 插槽同源（第一方） | [技术设计 24 · L1](../../技术设计文档/24-L1第一方能力包与流水线插槽.md) |
| 分期与落点 | [L2 执行索引](./L2第三方能力包_分期执行索引.md) |
| 类型 / 清单校验 / mock | npm 包 `@airpc/pack-sdk`（`packages/pack-sdk`） |
| 可抄示例 | 仓库 `examples/packs/*`、运行时样例 `plugins/demo-*` |

**契约冻结：** `apiVersion` **必须为 `1`**；槽点名与本文 §5 一致。增删槽点须同步 24、25、本手册与 SDK。

**本阶段不做：** ACL、权限裁剪、进程沙箱、签名审核。装错请卸包；作者与安装者自负。

## 0. 五分钟心智模型

```text
浏览器 UI（含插件 iframe）
  → Studio Next API 门面
    → 扫 workspace plugins/<id>/ + 能力 API
      → 与 L1 第一方包合流后注入 EngineHost
        → 引擎纯逻辑（不扫 plugins、不读作者磁盘路径）
```

| 层级 | 你做什么 | 放哪 |
|------|----------|------|
| L0 内容 | 故事卡 / 角色 JSON | `data/` |
| L1 第一方 | 引擎内静态能力包 | `packages/rpg-engine/src/capabilityPacks/`（**不是**你的交付物） |
| **L2 特性插件** | **本手册对象** | **工作区根 `plugins/<id>/`（与 `data/` 并列）** |

原则：

1. 能用内容卡表达的，优先内容；内容不够再写插件。
2. 官方用户 / 角色 / 记忆 / 外呼 **只经能力 API**，禁止依赖 `data/`、SQLite、Host 私有结构。
3. 插件私有逻辑与私有存储作者自理；宿主不规定私有根路径。
4. **Client 不执行** Node entry；逻辑只在 Studio server / 壳进程加载。
5. **通话中不热插包**；改清单或代码后需重启 Studio（装配有进程缓存）。

## 1. 最小可跑包（推荐照抄）

目标：开一场通话时，开场 soft 上下文多一段你的文字。

### 1.1 建目录

在仓库根（与 `data/`、`apps/` 同级）：

```text
plugins/hello-soft/
  capability-packs.json
  softExtra.mjs
```

也可先复制：

```bash
cp -R examples/packs/realtime-only plugins/hello-soft
# 然后改清单里的 id / name，并把 enabled 设为 true
```

### 1.2 清单 `capability-packs.json`

```json
{
  "id": "hello-soft",
  "name": "Hello Soft Extra",
  "version": "1.0.0",
  "apiVersion": 1,
  "enabled": true,
  "realtime": {
    "enabled": true,
    "pipelines": [
      {
        "slot": "begin.softExtras",
        "entry": "./softExtra.mjs"
      }
    ]
  }
}
```

要点：

- `id` 建议与目录名一致，全局唯一。
- `enabled: true` 才会加载；仓库内 `plugins/demo-*` 默认可能为 `false`，勿被样例误导。
- `entry` 相对**本包根**；禁止用 `../` 逃出包根（加载器会 `realpath` 校验）。

### 1.3 Entry `softExtra.mjs`

```js
/** @type {{ enricherId: string, apply: Function }} */
export default {
  enricherId: "hello.soft_extra",
  apply() {
    return "[hello-soft]\n这是我的第一段 soft 注入。";
  },
};
```

`enricherId` 须在全进程已加载包中唯一；与 L1 / 其它 L2 冲突会导致本包拒载。

### 1.4 验证

1. 重启 Studio（`npm run dev` 或等价）。
2. 打开调试器 → **Plugins** Tab，或请求 `GET /api/plugins/status`。
3. 应看到 `hello-soft` 在已加载列表；失败原因看 `plugin.load_failed` / status 里的 failures。
4. 用任意可拨角色开一场通话，检查开场 soft / 提示词侧是否出现你返回的字符串。

通了之后，再按 §5 加挂机任务、外呼、UI。

## 2. 目录与文件约定

```text
plugins/<id>/
  capability-packs.json     # 必填：清单
  *.mjs / *.js              # 各槽 entry（路径自定）
  ui/*.html                 # 可选：静态面板
  （可选子目录 realtime/ background/ ui/ —— 仅组织用，宿主不强制）
```

| 规则 | 说明 |
|------|------|
| 根目录 | 仅工作区 `plugins/`；引擎内核**禁止** `readdir(plugins)` |
| 启用 | **仅**清单顶层 `enabled`；无工作区总开关表 |
| 资产 | UI / entry 必须落在包根内；symlink 逃逸会失败 |
| 语言 | Entry 为 Node 可 `import` 的 ESM（推荐 `.mjs`） |

可选字段 `main`：包级初始化入口（清单 schema 支持）；业务贡献仍以各 `pipelines` / `panels` 的 `entry` 为准。

## 3. 清单完整参考

### 3.1 顶层字段

| 字段 | 必填 | 含义 |
|------|------|------|
| `id` | 是 | 插件 id，与目录名建议一致 |
| `version` | 是 | 作者版本字符串 |
| `apiVersion` | 是 | **字面量 `1`** |
| `enabled` | 是 | `false` → 整包跳过 |
| `name` | 否 | 展示名 |
| `main` | 否 | 可选总入口路径 |
| `realtime` | 否 | 实时通话域块 |
| `background` | 否 | 后台运行域块 |
| `ui` | 否 | 界面域块 |

某一大类不需要：省略该块，或写 `"enabled": false`。

校验可用 SDK：

```ts
import { parseCapabilityPacksManifest } from "@airpc/pack-sdk";
parseCapabilityPacksManifest(JSON.parse(raw));
```

### 3.2 域块与管道项

```json
"realtime": {
  "enabled": true,
  "pipelines": [
    { "slot": "begin.softExtras", "entry": "./softExtra.mjs" }
  ]
}
```

| 字段 | 含义 |
|------|------|
| `slot` | §5 槽点名（须落在对应域的合法枚举内） |
| `entry` | 相对包根的模块路径 |
| `after` / `before` | 可选；相对已有提供者 id 的插入暗示（清单层保留；排序以宿主合流为准） |

UI 块用 `panels`（不是 `pipelines`）：

```json
"ui": {
  "enabled": true,
  "panels": [
    { "slot": "settings.plugin", "entry": "./ui/settings.html" }
  ]
}
```

完整多域样例见：`examples/packs/realtime-background/`、`examples/packs/with-ui/`，以及技术设计 25 §4。

## 4. Entry 导出约定

加载器动态 `import(entry)`，按下列顺序解析贡献：

1. `export default { ...贡献本体 }` 或 `export default [ ... ]`
2. `export default function (api) { return 贡献 }`
3. `export default { contribute(api) { return 贡献 } }`
4. `export default { create(api) { return 贡献 } }`

其中 `api` 类型为 `PluginCapabilityApi`（见 §6）。

**硬约束：**

- **加载期不要调用**会碰 Host / 落盘的能力 API（Host 可能尚未就绪）。在钩子 `run` / `onTick` / 外呼决策函数里再调。
- 单 entry 可返回**一个对象或数组**；数组会逐项挂到同一槽。
- Entry 路径必须在包根内。

## 5. 槽点总表与贡献形状

槽点名 **apiVersion=1 已冻结**。下列「接线」以当前 Studio V2 为准：未接线槽写进清单不会阻断其它槽，但会记 `plugin.load_skipped` / `slot_not_wired:*`。

### 5.1 实时域 `realtime`

| 槽点 | 接线 | 时机 | 贡献形状（default 导出） |
|------|------|------|--------------------------|
| `begin.softExtras` | ✅ | 开场 soft 组装 | `{ enricherId, apply({ profile, userId, agentId }) => string \| null }` |
| `compose.providers` | ✅ | beginCall 合成提示词 | `{ providerId, apply(ctx) => void }`（`ctx` 为引擎 PromptProviderContext） |
| `call.afterHangup` | ✅ | endCall 同步段 | `{ hookId, run({ userId, sessionId, agentId, profile }) => void \| Promise }` |
| `commit.context` | ✅ | 组装 MemoryCommit | `{ enricherId, enrich({ userId, agentId, sessionId }) => object \| null }` |
| `commit.extract` | ✅ | 挂机抽取编排 | `{ contributorId, contribute({ userId, agentId, sessionId }) => object \| null }` |
| `tools.register` | ❌ | — | 清单可写；当前跳过 |
| `effects.register` | ❌ | — | 同上 |
| `dialogue.events` | ❌ | — | 同上 |

#### 示例：`begin.softExtras`

```js
export default {
  enricherId: "acme.weather_hint",
  apply(input) {
    // input.userId / input.agentId 可用；需要档案时用 input.profile
    return "【插件】请结合用户近况闲聊一句天气。";
  },
};
```

#### 示例：`call.afterHangup`（闭包拿 api）

```js
export default function create(api) {
  return {
    hookId: "acme.after_hangup_schedule",
    async run(input) {
      await api.tasks.register({
        taskId: `acme_followup_${Date.now()}`,
        fireAtMs: Date.now() + 5_000,
        payload: {
          userId: input.userId,
          characterId: input.agentId,
          chapterId: "your_chapter_id",
          cardId: "your_card_id",
          from: "afterHangup",
        },
      });
    },
  };
}
```

### 5.2 后台域 `background`

| 槽点 | 接线 | 时机 | 贡献形状 |
|------|------|------|----------|
| `tasks.onTick` | ✅ | 任务到期 | `{ taskId, onTick({ nowIso, packId }) => void \| Promise }` |
| `tasks.register` | ✅ | 包加载引导登记 | `{ taskId, register({ packId }) => void }` |
| `outbound.request` | ✅ | tick 后决策是否外呼 | `function (ctx) => decision`（见下） |
| `outbound.prepare` | ✅ | 外呼前准备钩子 | `function (input) => unknown`（可副作用 / 返回材料） |
| `schedule.gates` | ✅ | 调度是否放行 | `{ gateId, allow({ profile, nowIso }) => boolean }`（`false` = 推迟） |
| `schedule.topic` | ❌ | — | 清单可写；当前跳过 |

#### `tasks.onTick` 与 taskId 匹配

- 调度键为 `pluginId:taskId`。
- 若 `register` 时用了**动态** `taskId`（如带时间戳），而清单 entry 里写死的 `taskId` 对不上，宿主会回退到**该插件级** tick handler（demo 即此模式）。稳定产品包仍建议：**register 与 onTick 使用同一稳定 taskId**，或在插件内只挂一个兜底 onTick。

#### `outbound.request` 决策对象

`onTick` 之后，宿主会调用本包的 `outbound.request` 贡献。返回值（或结合 task `payload`）需能解析出外呼请求，否则不拨：

| 字段 | 来源 | 说明 |
|------|------|------|
| `shouldCall` | 返回值 | `false` 明确不拨 |
| `userId` | 返回值或 `payload` | 必填才能拨 |
| `characterId` / `agentId` | 同上 | 必填 |
| `chapterId` | 同上 | 必填 |
| `cardId` | 同上 | 必填；**必须**绑真实 CallCard，禁止伪造无卡 Session |
| `reason` | 可选 | 原因字符串 |

```js
export default function create() {
  return function request(input) {
    const p = input.payload ?? {};
    if (!p.userId || !p.characterId || !p.chapterId || !p.cardId) {
      return { shouldCall: false };
    }
    return {
      shouldCall: true,
      userId: p.userId,
      characterId: p.characterId,
      chapterId: p.chapterId,
      cardId: p.cardId,
      reason: "acme_followup",
    };
  };
}
```

也可在钩子内直接 `api.outbound.requestCall({ ... })`（须同样带齐 card/chapter）。

### 5.3 界面域 `ui`

| 槽点 | 接线 | Studio 挂载位置 |
|------|------|-----------------|
| `settings.plugin` | ✅ | 设置 · 引擎相关面板区 |
| `character.plugin` | ✅ | 角色库详情 |
| `user.plugin` | ✅ | 用户库详情 |

`entry` 指向**静态 HTML**（经 iframe + `sandbox="allow-scripts"` 托管）。

当前诚实口径：

- 面板由 `/api/plugins/panels` 列出，资源经 `/api/plugins/<pluginId>/assets/...` 提供。
- **尚未**向 iframe 注入可调用的能力 API 客户端 / postMessage 协议；面板适合说明文案、静态配置指引。
- 需要读写官方数据时，请用 **Node entry + 能力 API**（realtime/background），不要假设浏览器能直连引擎。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <title>Acme Settings</title>
  </head>
  <body>
    <h1>Acme 插件设置</h1>
    <p>本面板为静态说明；业务逻辑在 Node entry。</p>
  </body>
</html>
```

## 6. 能力 API（`api`）

注入每个 Node entry 的 `api: PluginCapabilityApi`（类型真源：`@airpc/pack-sdk` 的 `api.ts`）。

```ts
api.pluginId; // 与清单 id 一致
api.users / api.characters / api.memory / api.llm / api.session / api.tasks / api.outbound;
```

本地单测可用 `createMockPluginCapabilityApi()`。

### 6.1 矩阵与当前实现诚实口径

| 命名空间 | 方法 | 说明 |
|----------|------|------|
| `users` | `list` / `get` / `update` / `getCurrentContext` | `update` **当前仅持久化 `nickname`**；其它 patch 键可能被忽略 |
| `characters` | `list` / `get` / `getRuntime` / `updateRuntime` | `updateRuntime` **当前仅持久化 `unlocked`** |
| `memory` | `query` / `search` / `write` / `update` / `getProjection` | `update` 在 MemoryPort v1 上是**追加**新语义条，返回含 `appendedEntryId`、`inplaceUpdate: false`，**不是**原地改写 |
| `llm` | `chatText` / `chatStructured` | Key 与厂商在宿主侧；作者只传 messages / options |
| `session` | 见下 | 实时注入通道未全接线 |
| `tasks` | `register` / `cancel` / `list` / `get` | **按 pluginId 隔离**；`list` 只见本包；不能 cancel 别人的同名 taskId |
| `outbound` | `requestCall` / `getDialability` | `requestCall` 必须走宿主正式 beginCall；禁无卡 Session |

#### `session`（当前）

| 方法 | 状态 |
|------|------|
| `getSummary()` | 可用；无活跃会话时可能为 `null` |
| `subscribeEvents` / `injectSpeakable` / `reportToolResult` / `registerExitCandidate` | **显式未接线**：调用失败（`not_wired`），日志 `ok:false`。勿写成成功空操作 |

### 6.2 禁止事项

- 拼接 `data/`、SQLite 文件路径、引擎内部 Map
- 通话中直接改存档主链、绕过出口候选伪造推进
- 伪造无卡 CallSession / 自建「假外呼」
- 在浏览器插件页假设能 `import "@airpc/rpg-engine"`

## 7. 经典链路：挂机 → 定时 → 外呼

```text
通话 endCall
  → call.afterHangup（realtime）
      → api.tasks.register({ taskId, fireAtMs, payload })
  →（到期）tasks.onTick（background）
      → outbound.request 决策
          → api.outbound.requestCall（宿主绑 card 后正式外呼）
```

清单需同时声明（可参考 `examples/packs/realtime-background/` 与 `plugins/demo-hangup-task/`）：

1. `realtime.pipelines`：`call.afterHangup`
2. `background.pipelines`：`tasks.onTick` + `outbound.request`（可选 `outbound.prepare`）

外呼前宿主会跑本包 `outbound.prepare`（若有）。`payload` 里请带齐后续拨号所需的 `userId` / `characterId` / `chapterId` / `cardId`。

## 8. 调试与失败语义

| 手段 | 用途 |
|------|------|
| 调试器 **Plugins** Tab | 已加载包、槽点、失败原因 |
| `GET /api/plugins/status` | 同上的 JSON；含 `scanRootError`、事件环摘要 |
| 日志 type | `plugin.scan` / `load_ok` / `load_skipped` / `load_failed` / `slot_contrib` / `task_*` / `outbound_*` / `api_call` |

常见失败：

| 现象 | 原因 |
|------|------|
| 包完全不出现 | `enabled: false`；或未放在工作区 `plugins/`；或未重启 |
| `load_failed` + 冲突 | 与 L1 或其它已接受 L2 的 `packId` / `providerId` / `hookId` / `gateId` / `taskId` / `enricherId` 等冲突 |
| `load_skipped` + `slot_not_wired:*` | 槽名合法但 Studio 尚未挂主链（§5 标 ❌ 者） |
| `entry_outside_package_root` | entry/资产路径逃出包根 |
| UI 空态「暂无 … 面板」 | 无启用 UI 面板，或 UI 块 `enabled: false` |

单包失败默认**跳过该包**，不阻断引擎内核与其它包。

## 9. 与第一方（L1）的关系

- L1 在引擎内静态 merge；L2 在 Studio 扫盘后**追加**合流。
- **同名冲突时拒载 L2 包**（在 entry 真正执行贡献前即拒绝冲突包），并记 `plugin.load_failed`。
- 不要占用 L1 已有 `providerId`（例如内置 compose 链 id）；自用 id 建议加厂商前缀：`acme.*`。

## 10. 交付检查清单

发布 / 提测前自检：

- [ ] 目录在工作区 `plugins/<id>/`，`id` 与清单一致
- [ ] `apiVersion: 1`，顶层 `enabled` 按需为 `true`
- [ ] 每个 `slot` 属于正确域；贡献对象含正确 id 字段与函数
- [ ] 加载期不调能力 API；副作用放在 `run` / `onTick` / 决策函数
- [ ] 任务与外呼 payload 带齐 card/chapter；不伪造 Session
- [ ] 写接口按 §6.1 诚实范围实现（勿假设任意 patch 落盘）
- [ ] 重启后 Plugins Tab / status 显示 `load_ok`，无意外 `load_failed`
- [ ] 需要时用 `parseCapabilityPacksManifest` 校验清单
- [ ] UI 仅静态 HTML 时，文档/面板文案不承诺浏览器内 API
