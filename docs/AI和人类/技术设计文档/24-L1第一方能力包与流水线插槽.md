# 24. L1 · 第一方能力包与流水线插槽（中间态）

**状态：** L1 工程已落地（中间态，1.1+）；前置与 L1-A～E 已收口；**非**对外插件生态（L2 见 [25](./25-L2第三方能力包与SDK.md)）。  
**定位：** 固定引擎主链；把可扩展点收成**具名插槽**；用**第一方 CapabilityPack** 验证装配。插槽命名与两大运行域与 [25](./25-L2第三方能力包与SDK.md) **同构**，便于日后迁出到 workspace `plugins/`。  
**不做：** 第三方扫描、UI 面板协议产品化、ACL、私有存储规范。  
**对外契约：** 与 25 同名的 realtime/background 槽点及 `apiVersion=1` **已冻结**（L2-0）；增删须同步 25 与 [L2 执行索引](../里程碑/v2.0/L2第三方能力包_分期执行索引.md)。

| # | 目标 | 完成判据 |

## 2. 为何需要 L1

```text
现状：Prompt Provider 已像流水线；Effect / tick / 挂机后任务仍深耦合
风险：51 增强继续堆 Host → 框架努力白费
直接上 L2：无稳定槽点 → 第三方清单无处可挂
```

顺序：**L1 钉槽点与第一方装配 → L2 开放 workspace plugins 清单与完整 API**。

## 3. 内核 vs 插槽

### 3.1 内核（不可做成「可关插件」换掉）

| 块 | 说明 |
|----|------|
| CallIntent → Resolver → beginCall / Session | 一通电话一张卡 |
| Opening First-Turn 幂等 | 首句门闩 |
| 通话中只登记 RuntimeExitCandidate | 推进在挂机后 |
| Free：MemoryCommit →（有候选）Exit → Effect | 顺序固定 |
| Port 边界 | 引擎不实现 fs/sqlite |
| 外呼必须正式入口 | 不可伪造无卡会话 |

### 3.2 插槽总表（与 25 同构）

#### 实时通话域 realtime

| 槽点 | L1 成熟度目标 | 现况 |
|------|---------------|------|
| `compose.providers` | Pack 可贡献 | ✅ Registry + merge + core-compose |
| `begin.softExtras` | Registry 化 | ✅ Pack enricher → Host softExtras；内置 memory/lore/FC 仍函数组装 |
| `tools.register` | 可合并定义 | ✅ builtin 表（Pack 合并未接） |
| `effects.register` | 表化可后置 | ✗ switch（L1 不要求） |
| `dialogue.events` / flow | 表 + 默认实现 | △ 选型函数 |
| `call.afterHangup` | **必须留钩**（可先薄实现） | ✅ 钩子表 + endCall 转调；时序=outcome 后、Free/Story 分支前（非整条挂机流水线末尾）；失败记 `afterHangup_failed` |
| `commit.context` | enricher 可挂 | ✅ merge + Studio MemoryCommit Orchestrator → `packExtras` |
| `commit.extract` | server 侧贡献点形状 | ✅ merge + Orchestrator 同袋 |

#### 后台运行域 background

| 槽点 | L1 成熟度目标 | 现况 |
|------|---------------|------|
| `schedule.gates` | 统一门闩链 | ✅ outbound-window-gate 经 merge→Host 注入；显式 `[]`=关包无闸；判定打 `schedule_gate` 日志 |
| `schedule.topic` | 接口 + noop/样例 | ✗（形状未强制） |
| `tasks.register` / `tasks.onTick` | **接口形状 + 最小宿主定时** | ✅ merge；Host 创建时 `register` 一次；onTick 定时未产品化 |
| `outbound.prepare` / `outbound.request` | 接口形状；请求走既有 outbound | △ 有 outbound，Pack 贡献点未接 |

**L1 底线：** `compose.providers` + 装配可用 + `call.afterHangup` 钩子可挂第一方逻辑；`commit.*` 与 `tasks.*` 至少有类型与可挂点，避免 L2 才发现主链无槽。

## 4. 第一方 CapabilityPack 契约

```ts
interface FirstPartyPackManifest {
  packId: string
  packVersion: string
  apiVersion: 1
  /** 与 L2 清单域对齐，便于迁出 */
  domains: Array<"realtime" | "background">
}

interface FirstPartyPack {
  manifest: FirstPartyPackManifest
  contribute: {
    /** 按槽点贡献；实现期可细化为与 25 entry 同构的注册表 */
    realtime?: Partial<Record<RealtimeSlot, unknown>>
    background?: Partial<Record<BackgroundSlot, unknown>>
  }
}
```

装配：

```text
Studio server / 测试
  → 静态 import 第一方 capabilityPacks
  → mergeCapabilityPacks（独立模块；按 packId 开关）
  → 合并进 registries / 钩子表
  → createEngineHost(…) / getEngineHost(…)
```

**禁止：** 引擎内核 `readdir(plugins)`；在 beginCall / effect 中段直接堆特性。

### 4.1 第一方代码落点（对内）

```text
packages/rpg-engine/src/capabilityPacks/
  _core/                 # core-compose 等
  realtime/
    user-location/       # F-10 样板（L1-C）
  background/
    outbound-window-gate/
apps/studioV2/src/utils/server/capabilityPacks/   # 装配（非 server/packages）
```

对内可用子目录方便开发；**对外 L2 不要求、也不镜像这套分类到 workspace `plugins/`。**  
日后若某第一方包迁出：目标目录 = workspace `plugins/<id>/`（见 25），不是引擎内再建 `plugins/`。

### 4.2 启用（仅第一方运维）

L1 可用 server 装配清单或测试夹具开关某 `packId`。  
**L2 启用规则不在此文件：** 见 [25](./25-L2第三方能力包与SDK.md)——各包自己的 `capability-packs.json` → `enabled`。

## 7. 测试与门禁

- 重复 packId / providerId → 失败  
- 关非 core 包仍可 Free 通话  
- `capabilityPacks` 禁 react/next；Client 禁 import 引擎 `capabilityPacks`（含深挖路径）  
- L1 代码任务：`verify: npm run quality:engine`；触碰 Host/effect/schedule 基线文件不得净增受控指标

## 8. 原则

1. 薄架构，厚样板。  
2. 主链不可关；变换可拔。  
3. LLM 抽取/选题实现留在 Studio server，经槽贡献，不进引擎包内调 Key。  
4. 下游 L2 的开放能力与「不管私货」口径以 25 为准；L1 不提前做权限产品。
