# 17. 版本迁移与兼容策略

相关：[07-壳嵌入与导出契约](./07-壳嵌入与导出契约.md) · [10-用户与存档](../需求/10-用户与存档.md)

## 1. 版本字段

内容包与 SaveGame 均含整数 `schemaVersion`（v1 起为 `1`）。

未来若拆 major/minor，约定：

```text
schemaVersion = major          // v1 仅整数
或 schemaVersion: { major, minor }  // 若升级格式，另文定义
```

本文 v1 按 **单一整数 major** 描述策略；语义对齐如下。

## 2. 加载策略

| 情况 | 行为 |
|------|------|
| 版本 == 引擎支持版本 | 正常打开 |
| 版本 < 支持，且存在 migration | 纯函数迁移到当前版本后打开 |
| 版本 < 支持，且 **无** migration | **只读**打开（或拒绝编辑/导出）；提示升级路径 |
| 版本 > 引擎支持（未知更新） | **拒绝**加载，提示升级 Studio/引擎 |

```text
unknown newer version → reject
older version + migration → migrate (pure function)
older version + no migration → readonly (or soft-fail with message)
migrations are pure: (oldDoc) => newDoc，无 I/O 副作用
```

## 3. Migration 实现要求

- 放在 `packages/rpg-engine` 内，按版本链 `1→2→…→current`
- 单测：夹具旧包迁移后通过当前 Zod schema
- 迁移不得静默丢关键字段；无法映射则写入 `migrationWarnings[]`

## 4. 内容包 vs SaveGame

- 两者可独立升版本，但尽量同号
- SaveGame 迁移须保留 `userId` 与进度语义

## 5. Studio

- `file.schemaVersion > SUPPORTED` → **拒载**；Dialog：「此内容由更新版引擎编写，请升级 Studio」
- `file < SUPPORTED` 且无 migration → 拒载或只读横幅（v1 仅版本 1 时非 1 一律 reject）
- 列表项禁用；**禁止**静默损坏数据
- 导出前可「另存为当前版本」（有 migration 时）

## 6. v1 当下

- 仅 `schemaVersion: 1`；`SUPPORTED_SCHEMA = 1`
- 无 migration 表时加载非 1 一律 `SCHEMA_UNSUPPORTED`（见 [19 §15–16](./19-引擎宿主与会话模型.md)）

## 7. 故事包嵌套与 Profile 迁移（包 ⊃ 章升档）

与 [19 §3.5](./19-引擎宿主与会话模型.md) 对齐；迁移函数放在 `packages/rpg-engine` 或 `engineIOModule`，**纯函数 + 单测**，无隐式网络 I/O。

### 7.1 扁平目录 → 嵌套 `chapters/`

| 旧路径 | 新路径 | 规则 |
|--------|--------|------|
| `storis-packages/<packageId>/story.conf.json` | `…/chapters/<chapterId>/story.conf.json` | 默认 `chapterId = packageId`；conf 内补 `chapterId` 字段 |
| `…/cards/*.s-card.json` | `…/chapters/<chapterId>/cards/*` | 整目录搬迁 |
| `…/canvas.layout.json` | `…/chapters/<chapterId>/canvas.layout.json` | 旁车随章 |
| （无） | `…/package.conf.json` | 新建；`entryChapterId = chapterId`；`chapters[]` 登记首章 |

- IO 在 `loadWorkspaceSnapshot` 或专用 `rematerializePackageLayout` 中检测「包根存在 `story.conf.json` 且无 `package.conf.json`」→ 触发迁移。
- 迁移幂等：已有 `package.conf.json` 则跳过。
- 无法映射的字段写入 `migrationWarnings[]`，不得静默丢弃 `entryCardId` / `cards[]`。

### 7.2 `end_story.next.packageId` → `next.chapterId`

旧 effect / 编辑器投影若仍写 `next.packageId`（跨包续章）：

| 旧字段 | 新字段 | 规则 |
|--------|--------|------|
| `next.packageId`（跨包） | — | **拒绝**或迁移 warning：v1 仅允许同包 `next.chapterId` |
| `next.packageId`（与当前包相同） | `next.chapterId` | 若旧语义「下一章 = 另一 packageId 且 id 不同」→ 需人工拆包；若实为同包续章则 `chapterId = 旧 packageId 或显式章 id` |

迁移纯函数：`(oldEndStoryEffect, currentPackageId) => newEndStoryEffect`；缺 `chapterId` 时写入 `migrationWarnings[]`。

### 7.3 Profile `stories` 字段

旧 Profile 以 **packageId 为唯一键** 记录章节进度；升档后以 **`packageId + chapterId`** 为逻辑键（实现可嵌套 `profile.stories[packageId].chapters[chapterId]` 或扁平键 `` `${packageId}/${chapterId}` ``，须在 schema 注释钉死）。

| 旧 | 新 | 规则 |
|----|-----|------|
| `stories[pkg].status` | `stories[pkg].chapters[ch].status` | 扁平旧包迁移：`ch = pkg`（与 §7.1 默认 chapterId 一致） |
| `stories[pkg].plannedEntry.cardId` | 同上 + **`chapterId` 必填** | 缺章 id 时用 `entryChapterId` 或默认章 |
| `appliedEffectIds` 等摘要 | 按章分区或带 `chapterId` 前缀 | 避免跨章幂等混淆 |

SaveGame 迁移须保留 `userId` 与进度语义；无法映射的进度 → `migrationWarnings[]` + 只读横幅，**禁止**静默丢档。

### 7.4 导出格式废弃

- ~~`airpc.contentpack.v1`~~：导入时提示「请拆为 storypack 或升级 Studio」；不提供自动拆包写盘（降低误覆盖风险）。
- 正式导出仅 **`airpc.storypack.v1`（整包，含 `package.conf` + 全部 `chapters/`）**。
