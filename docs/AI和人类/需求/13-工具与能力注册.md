# 13. 工具与能力注册（ToolRegistry）

相关：[01-CallCard数据模型](./01-CallCard数据模型.md) · [15-动态出口与通话中工具事件](./15-动态出口与通话中工具事件.md) · [50-对话与模型适配](./50-对话与模型适配.md) · [19](../技术设计文档/19-引擎宿主与会话模型.md)

## 1. 问题

卡上仅有 `toolPolicy.allowedToolIds: string[]` 不够：编辑器不能只填自由字符串；校验器需知道工具是否存在、是否允许用于 story/free、是否在 `playback_only` 下禁用。

## 2. ToolRegistry 条目

```ts
interface ToolDefinition {
  toolId: string
  displayName: string
  description: string
  inputSchema: unknown          // JSON Schema / Zod 导出
  allowedCardKinds: Array<"free" | "story" | "system">
  /** 为 false 时任何 playback 阶段不可用 */
  allowedInPlayback: boolean
  runtimeGuards?: {
    requiresStoryLock?: boolean
    requiresCanIntroduce?: boolean
    maxCallsPerSession?: number
  }
  behavior: "register_exit" | "session_local" | "shell_control" | "external"
  /** 登记出口时的模板（可选）；挂机才实例化为 Effect */
  exitCandidateTemplate?: {
    exitKind?: ExitKind
    priority?: number
    effectTemplateIds?: string[]
  }
}

interface RegisteredTool {
  definition: ToolDefinition
  source: {
    kind: "builtin" | "shell" | "l1" | "plugin"
    providerId: string
    displayName: string
  }
  inheritByDefault: boolean
  invoke?: ToolInvokeHandler
}
```

- `register_exit`：通话中只登记 candidate，挂机后 Effect。  
- `session_local`：**只读或仅本通展示**（如记忆召回）；**不写 Profile / Memory DB 业务态**（查询结果回给模型即可）。
- `shell_control`：只产生归一化壳事件；物理断线等媒介动作仍由壳执行。
- `external`：由 L1 / L2 注册的受控 handler；调用仍须经过 Host 策略与参数校验。

**运行时唯一真源 = 注入 EngineHost 的 `ToolRegistry`。** `builtinRegistry` 只是默认贡献源；Studio Server 在启动 / `loadWorkspace` 时将内置、壳、L1 与已启用 L2 贡献合流后注入 Host。引擎内核不扫描 `plugins/`。每次合流生成稳定 `revision`；`beginCall` 冻结本通 revision 与实际工具集合，后续插件变更只影响新通话。

L2 本地 id 由宿主标准化为 `plugin:<pluginId>:<localToolId>`；任何来源之间的 toolId 冲突都拒绝装配，不允许后加载者覆盖。

**与旧话机差异（定稿）：**  
doubaoSister 在通话中 FC handler **立刻写 store/调度/挂机**。本引擎业务工具改为：通话中只 `register_exit` → 挂机后 ExitSelector / FreeCallPostPipeline → Effect（+ Sink）；壳控制工具则登记壳事件，断线后统一进入 `endCall`（见 §7.2）。
旧仓是**功能参考**，不是实现继承；inputSchema 见 §6.1。

### 2.1 给模型的双通道（description + 剧本块）

| 通道 | 落点 | 用途 |
|------|------|------|
| **短 description** | `ToolDefinition.description` → `DialogueSessionSpec.tools` | 何时调、与兄弟工具一句分流、只登记候选 |
| **字段说明** | Zod `.describe` → `inputSchema.properties.*.description` | 参数例子（如「豆豆」「小卖部暗号」） |
| **剧本块** | `buildToolInstructionBlocks(allowedToolIds)` → `RenderedPrompt.softContext`（`[tools]`） | 负例、时序、notify_mode、交叉互斥 |

- 剧本块按**本通实际开放**的 toolId 裁剪；仅当相关工具同时开放时注入「专家优先于研究」「reminder vs recurring」等交叉句。  
- `beginCall` 与首通预览同口径注入；`deny_all` 不追加。  
- `request_hangup` 与插件 FC 同样只按本通实际开放集合进入模型请求；不存在旁路追加。

### 2.2 首句阶段工具边界

Opening First-Turn 不是普通工具调用阶段。`consumeOpeningFirstTurn` 消费首句时：

- `direct`：Host 直接写 assistant 首句，不开放任何工具。
- `request_llm_opening`：首句 LLM 仅生成开场文本；不得携带 tool calls。
- `already_emitted` / `skipped`：直接进入后续普通对话；工具开放从普通轮次开始。

**禁止：**

- unknown inbound 首句阶段调用 `search_memory` / `get_memory_by_id` 获取用户身份。
- 首句 LLM 通过业务工具登记 ExitCandidate。
- Studio / 壳为了补 opening 绕过 Host 工具策略，自行把 tools 塞进首句 LLM。

## 3. 与 toolPolicy

```ts
interface ToolPolicyV2 {
  schemaVersion: 2
  mode: "inherit_free" | "allowlist" | "deny_all"
  allowedToolIds?: string[]
  options?: {
    request_hangup?: {
      allowedReasonKinds: Array<"natural" | "policy" | "handoff">
    }
  }
}
```

解析规则：

1. `playback_only` 与 voicemail → 强制无工具。
2. `deny_all` → 最终集合为空，壳与插件工具也不得例外。
3. `allowlist` → `allowedToolIds ∩ Registry ∩ cardKind ∩ characterCapability`。
4. `inherit_free`（Free 卡默认；旧卡无 policy 时同此）→ 只继承 `inheritByDefault=true` 且满足上下文约束的核心工具；插件工具永不自动进入。
5. 在 `inherit_free` 卡选择插件 FC 时，编辑器先把当时有效核心集合复制为 `allowlist`，再加入插件 toolId，避免隐式扩大权限。

旧 policy 由幂等规范化迁移到 v2。已选择但当前 provider 缺失的 id 继续保留在 JSON，Studio 显示“插件不可用”，允许保存草稿，但禁止调试与正式导出。

## 4. 校验规则（补充）

| ruleId | 级别 | 说明 |
|--------|------|------|
| `TOOL_UNKNOWN` | error | allowedToolIds 含未注册 id |
| `TOOL_KIND_MISMATCH` | error | 工具不允许该 cardKind |
| `TOOL_PLAYBACK` | error | playback_only 仍声明工具 |
| `TOOL_DIRECT_EFFECT` | error | 试图把工具标成通话中直接 effect |

完整规则总表见 [08-内容校验规则](./08-内容校验规则.md)。

## 5. Studio

- Server API 按 `agentId + cardKind + interactionMode` 投影动态工具目录；Client 禁止 import 引擎值或维护静态镜像。
- 目录按通话控制、引擎内置、角色专属、插件能力、已失效配置分组，并展示来源、可选原因、角色声明与插件加载状态。
- Prompt 预览、调试器、LLM payload、运行时调用和内容校验共用同一 Registry 与策略解析器。

## 6. 工程约束

- 壳侧 Realtime `session.update` tools 由 **Adapter** 从 Registry 投影为厂商 schema；引擎不写 DashScope/OpenAI 嵌套格式
- `Host.invokeTool` 是所有 FC 的唯一分发入口；Studio / 壳不得按 toolId 建旁路 handler。
- Adapter 只封装 `function_call_output`；成功、拒绝与标准工具错误均来自 Host。
- 插件参数先按 JSON Schema 校验；handler 默认 10 秒超时；结果须可 JSON 序列化且不超过 32 KiB。失败不结束会话、不伪造成功。

### 6.1 inputSchema 真源（定稿）

```text
需求真源：本文 §7 参数要点（语义与必填字段）
实现真源：引擎内 Zod（或等价）建模 → 导出 JSON Schema 给 Adapter
旧仓 schema：仅设计时对照「缺没缺字段」（如 weekdays、notify_mode）；对得上即可
```

- **禁止**把 doubaoSister 的 JSON Schema / config 文件拷进本仓当实现  
- 需求文档保持参数摘要即可；schema 全文是实现产物，不必堆进需求文  
- Adapter 只消费引擎导出的 schema，不直读旧仓文件

## 7. v1 内置工具清单（能力对标 doubaoSister）

来源对照：旧仓 `buildAllSessionTools` 及各工具 config（**只读对标，不搬文件**）。  
**toolId 可保持旧名**，便于和实机能力清单对照；语义与执行按本引擎铁律重绑（`register_exit` → 挂机 Effect）。

### 7.1 进引擎 Registry（`behavior: register_exit`）

默认 `allowedCardKinds: ["free","story"]`（system / playback 阶段禁用）；`allowedInPlayback: false`。

| toolId | 显示名 | 功能（旧 description 摘要） | 参数要点 | 挂机后 Effect 方向 |
|--------|--------|------------------------------|----------|-------------------|
| `refer_to_expert` | 安排专家回电 | 安排目标角色稍后主动来电（引荐） | `target_agent_id`, `topic_hint`；可选 `referral_style` | `set_character_unlocked` + `schedule_call_card`（目标 Free/剧情卡）+ 可选目标卡 `attach`；**不设 Relay**；须 `social.canIntroduce`（guard） |
| `share_expert_number` | 已口播专家号码 | 用户已知晓对方号码（报号路径） | `target_agent_id`, `topic_hint` | `set_character_unlocked`；可选 `update_npc_knowledge` / `patch_memory` hints |
| `schedule_reminder_call` | 预约回电提醒 | X 分钟/小时后回电提醒某话题 | `topic_hint`；`delay_minutes` **或** `delay_hours`；可选 `confirm_phrase` | `schedule_call_card`（本通角色或约定角色；delay → minMs） |
| `schedule_recurring_call` | 登记重复外呼 | 每天/每周定时外呼（旧 corn） | `topic_hint`, `hour`(0–23), `minute`, `schedule_mode`:`daily`\|`weekly`；weekly 要 `weekdays`；可选 `job_id` | Effect `schedule_recurring_call` → `ScheduledIntent.kind: "recurring"`；壳 Sink 执行真定时 |
| `record_shared_secret` | 登记共同秘密 | 只存代号与回忆提示，不含完整秘密 | `label`, `recall_hint` | `patch_memory`（semantic / commitments）或 fact；禁止通话中写 |
| `create_research_commitment` | 研究承诺 | 挂机后查资料再告知 | `question`；可选 `notify_mode`:`next_call`\|`intent`\|`urgent` | Effect `create_research_commitment` → **唯一**写 `Profile.research.commitments`（见 [10](./10-用户与存档.md)）；联网在通话外 |
| `record_user_name` | 登记用户称呼 | 孩子自报昵称/姓名 | `nickname`；可选 `full_name` | Effect `update_user_profile`（写 `Profile.user`）；可另 `patch_memory` 本通角色「初识」备注 |

**候选模板约定：**

- 纯动态 candidate 须自带 `effects`（由 Registry 模板在登记时展开或挂机实例化）。
- `refer_to_expert` / `share_expert_number`：`runtimeGuards.requiresCanIntroduce: true`（对 `target_agent_id`）。
- 同通 `refer_to_expert` 与 `share_expert_number`：旧仓互斥路径；v1 校验 **warning**（可并存但调试器标黄）。

**Free 默认：** `inherit_free` → §7.1 业务工具 + §7.1b 记忆召回（凡 `allowedCardKinds` 含 free）。  
**Story 默认：** 建议 allowlist；记忆召回可按卡开放。

### 7.1b 记忆召回（`behavior: session_local`，只读）

**不进**旧话机业务 FC 列表；为本引擎补强（旧仓无检索、仅硬截断）。  
算法与 FTS DDL 见 [20 §5](../技术设计文档/20-记忆存储与投影.md)。

| toolId | 显示名 | 参数要点 | 行为 |
|--------|--------|----------|------|
| `search_memory` | 搜索记忆 | `text_query?` 与时间窗 `from`/`to` **至少一个**；可选 `kinds[]`；`max_results`（默认 5，硬上限 10） | `MemoryPort.search` → 短列表（id+**≤200 字**摘要+时间）；**查 SQLite FTS**；禁止全表灌 prompt |
| `get_memory_by_id` | 按 id 取一条 | `entry_id` | `MemoryPort.getById`；须同 user+agent；正文 **≤500 字** |

- 通话中可用；**不**登记 Exit、**不**写库（除审计 log）。  
- `userId`/`agentId` 由 Host 注入；v1 禁止跨角色搜。  
- 超时/过多 → 工具错误信息，不拖死通话。  
- **v1 = 字面 FTS**（可 LIKE 降级）；**不做**向量语义检索。  
- Opening First-Turn 阶段不可用；unknown inbound 首句前不得用记忆工具反查来电者身份。

**工具描述应引导模型：**

1. 「N 年前」→ 先估 `from`/`to`，再带 `text_query`  
2. 先 `search_memory`，摘要不够再 `get_memory_by_id`  
3. 空结果 → 承认没查到或换词；禁止假装记得  

详见 [12](./12-记忆模型.md)、[20 §5](../技术设计文档/20-记忆存储与投影.md)。

### 7.2 主动挂机 FC（决策过引擎 · 断线在壳）

NPC/模型**主动结束通话**的能力（非用户摘挂机动作）。定稿口径：

```text
模型调 request_hangup({ reasonKind, reason? })
  → Host.invokeTool：按冻结集合与 reasonKind 选项校验
  → 引擎登记 shell event（不直接断线）
  → 壳播告别 / 真断线
  → endCall({ termination: { source: "npc", reasonKind, reason } })
  → MemoryCommit / Exit / Effect（与用户挂机同一管线）

用户挂机：
  壳上报 endCall(source=user) → 引擎记账 → 同一挂机后管线
```

仅保留一个 `request_hangup`：`reasonKind=natural | policy | handoff` 分别表示自然道别、策略终止、引荐完成。三种原因必须在卡片 `options` 中显式允许；本通用户尚未开口时拒绝调用，`handoff` 还要求已经登记引荐候选。

用户手动挂机写 `termination.source="user"`；异常或宿主终止写 `source="system"`。旧 `context.studioShellHangup` 在导入 / 保存规范化时转换到 v2 options 并删除旧字段。

### 7.3 旧 → 新行为对照

```text
旧：FC → handler 立刻写 store / 调度 / 挂机 → function_call_output 续说
新：业务 FC → ToolRuntime → RuntimeExitCandidate
      → session.ended
      → Story: ExitSelector | Free: PostPipeline（Commit + 有候选则 Exit）
      → Effect (+ Sink)
新：主动挂机 FC → Host 策略守卫 → shell event → 壳断线 → 同一 endCall 管线
```

### 7.4 磁盘与真源

| 路径 | 角色 |
|------|------|
| `packages/rpg-engine/src/tools/builtinRegistry.ts` | 内置默认贡献源；不是 Host 装配后的唯一集合 |
| Studio Server L1/L2 装配 | 合流贡献，生成 Registry revision，注入 EngineHost |
| `data/tools/registry.json` | **非真源／预留**（可作人类可读导出副本；引擎 **无读路径**，勿当编辑或加载源） |

L1 `tools.register` 与已启用 L2 `tools.register` 已接线。L2 的 `effects.register`、`dialogue.events` 仍明确未接线；任何磁盘 JSON 都不能覆盖 Registry。

## 8. v1 范围与非目标

- **已接线：** §7.1 七支 + §7.1b 记忆召回、单一 `request_hangup`、L1 / L2 `tools.register`、动态目录与统一 Host 调用。
- **可后做：** research 真联网、corn UI、密钥加密、**向量召回**、L2 `effects.register` / `dialogue.events`。
- **不做：** 通话中直接 Effect；拷贝旧 schema；全量 JSON 扫记忆灌模型；引擎内实现 GPIO/ALSA 断线
