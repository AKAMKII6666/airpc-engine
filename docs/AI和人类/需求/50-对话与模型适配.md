# 50. 对话与模型适配 · 上下文合成

相关：[02](./02-运行时协议.md) · [18](../技术设计文档/18-部署拓扑与BS架构.md) · [12](./12-记忆模型.md) · [01](./01-CallCard数据模型.md) · [19](../技术设计文档/19-引擎宿主与会话模型.md)

## 1. 问题

电话壳使用 **全双工 Realtime**；Studio 调试用 **文本模型**（或 Manual）模拟同卡语义。  
引擎只认 Dialogue 端口与事件，**禁止**把厂商 Realtime/Chat SDK 写进核心状态机。

## 2. 部署口径（Studio）

```text
浏览器：聊天 UI（输入、流式展示、挂机按钮）—— 不持 API Key、不直连大模型
Next server：TextDialogueAdapter + LLM 调用（Key 在 server）
rpg-engine：会话事件、动态出口登记、挂机后 Outcome/Exit/Effect
```

浏览器侧的「执行」= **演 UI**；模型接入与领域推进都在 **server**。详见 [18](../技术设计文档/18-部署拓扑与BS架构.md)。

## 3. 两端口

### 3.1 DialogueAdapter

```ts
type DialogueChannel = "realtime_audio" | "text_turn" | "manual"

interface DialogueAdapter {
  readonly channel: DialogueChannel
  start(spec: DialogueSessionSpec): Promise<void>
  update?(patch: DialogueSessionPatch): Promise<void>
  sendUserText?(text: string): Promise<void>
  stop(reason: string): Promise<void>
  subscribe(handler: (ev: DialogueEvent) => void): () => void
}

interface DialogueSessionSpec {
  sessionId: string
  channel: DialogueChannel
  card: CallCardDefinition
  instanceId: string
  prompt: RenderedPrompt
  composeScene: ComposeScene
  /** 已按 toolPolicy ∩ Registry 过滤；壳挂机 FC 不在此列 */
  tools: ToolDefinition[]
  interactionMode: InteractionMode
  playback?: { assetId: string; transcript?: string }
}

interface DialogueSessionPatch {
  /** 过程话术注入等；v1 以追加为主 */
  appendSpeakable?: string
  appendPrivate?: string
  tools?: ToolDefinition[]
}
```

`DialogueSessionSpec` 由 beginCall → Composer 后交给 Adapter；过程话术经 `update` 注入（见 §5.6）。

**正交性：**

- 卡上 `interactionMode` = 剧情意图
- `DialogueChannel` = 音频双工 / 文本轮次 / 人工点选

可用 `text_turn` 跑 `interactionMode: realtime_dialogue` 的卡。

interface OutcomeEvaluator {

## 5. ContextComposer

### 5.1 类型定稿

```ts
interface ComposeScene {
  callDirection: "inbound" | "outbound"
  localTime: {
    isoWithOffset: string   // 用户墙钟，含 offset
    timeZone?: string       // 壳/浏览器上报；User 不存 timeZone 真源
    localHour: number       // 0–23；promptScenes 仅按 localHourRange 匹配
  }
  /** Free 默认可自然提及时段；Story 默认只校正用语 */
  timeMentionPolicy: "allow_casual" | "correct_only"
}

interface RenderedPrompt {
  systemHard: string[]
  openingSpeakable?: string
  openingPrivate?: string
  speakable: string
  private: string
  softContext: string[]
  matchedLayerIds: string[]
  /**
   * 首句运行控制的 Composer 产物；beginCall 后提升为 CallSession.openingFirstTurn。
   * 运行期真源与幂等消费见 19 §2.1。
   */
  openingFirstTurn?: {
    mode: "none" | "direct" | "llm_opening"
    status: "pending" | "emitted" | "skipped"
    text?: string
    callerVisibility?: "unknown" | "identified"
    allowMemoryBeforeUserSpeaks?: boolean
    allowInertiaBeforeUserSpeaks?: boolean
    allowNameBeforeIdentified?: boolean
    forbidden?: string[]
    llmContextPolicy?: OpeningLlmContextPolicy
  }
  debug?: {
    providerIds?: string[]
    notes?: string[]
  }
}

interface OpeningLlmContextPolicy {
  includeSystemHard: boolean
  includeSpeakable: boolean
  includePrivate: boolean
  includeSoftContext: boolean
  includeMemory: boolean
  includeInertia: boolean
}
```

`BeginCallOpts.localNowIso` / `timeZone` → Host 填 `composeScene`。缺省：请求到达时的 UTC + 上报时区；再缺 Studio v1 可用 `Asia/Shanghai`。**不以 User.location 当墙钟真源。**

### 5.2 Prompt Provider 组装管道（固定顺序，可测）

```text
compose({
  user, characterDef, memoryProjection, card,
  worldLore, worldFactsVisible, scene: ComposeScene
}) → RenderedPrompt
```

Composer 由 Prompt Provider Registry 驱动；内置 provider 顺序是实现级 contract，外置 provider 只能通过 registry 插入，不能在 Studio / 壳侧绕过 Host 拼 system。

```text
1. base ← card.context（objective / forbidden / private / speakable / emotion…）
2. 本通 card.promptScenes（若有）按 match + priority 应用
3. 若本通未产出 opening*：回落 CharacterDef.defaultPromptScenes（同构 match；仅日常兜底）
4. Opening Situation Resolver 判断开场事实（呼入/呼出、预约回电、未接外呼、时段、mailbox/story 等）
5. Opening Provider 根据 situation 决定 openingSpeakable / openingPrivate / openingFirstTurn
6. 注入全局电话口语 Style Policy（短句、少舞台描写、不要剧情式“自我介绍长独白”）
7. 注入 call source / scheduled callback / missed outbound 等电话媒介 hard block
8. 注入角色 `persona.systemPrompt`（hard）、`persona.personalityCode`（hard）与角色级风格；`identity` 进 soft
9. 注入「时间意识」块（每通必有，见 5.4）—— hard
10. 叠 Lore / Facts(可见) / Memory soft（投影须带记忆条目时间 / 相对「多久以前」；见 [12](./12-记忆模型.md)）
11. 叠 conversation.inertia（仅普通对话；首句是否可见由 openingFirstTurn policy 控制）
12. 输出 RenderedPrompt（含 matchedLayerIds / debug.providerIds / openingFirstTurn）
```

只读，不写 Profile。  
优先级摘要：

```text
卡 hard（objective/forbidden）
  → 本通 promptScenes
  → 角色 defaultPromptScenes（日常兜底；不承载剧情 opening）
  → Opening Situation / Opening Provider
  → 全局电话口语 style + 电话媒介 hard block
  → persona.systemPrompt + persona.personalityCode + 角色风格 + identity
  → 用户本地时间注入
  → Memory / Lore / conversation.inertia
```

### 5.3 Opening Situation / Opening Provider

Opening Situation Resolver 只判断“这通电话的接通事实”，不直接写业务状态；Opening Provider 才生成可说首句、私有提示和 first-turn 控制。

| situation | 来源 | openingFirstTurn |
|-----------|------|------------------|
| 玩家主动拨入、未知来电 | `actualEntry=inbound_user_dial` 或 `callDirection=inbound`，且非 story/schedule/missed/mailbox | `direct`；短句接听；`callerVisibility=unknown`；首句前禁 memory / inertia / name |
| NPC 预约/计划回电 | schedule / expert referral / recurring / story scheduled 来源 | `llm_opening` 或普通 LLM；允许带预约话题 |
| 未接外呼恢复 | missed outbound 标记 | 普通 LLM；不得装作陌生来电 |
| Story / simulate | 当前卡控制 opening | 卡级 `promptScenes` / context 优先 |
| Mailbox playback | 信箱卡控制 | playback 语义，不进入普通开场 |

**设计边界：**

- Free card 和角色 default opening 只能做日常兜底，不承载“打错电话”这类剧情 opening。
- 剧情 opening 应落在 Story 卡 `promptScenes` 或明确的 Opening Provider 规则。
- 时间 opening 只允许轻微影响接听感，如“这么晚了”；不得把时段扩写成固定剧情。

### 5.4 时间意识注入（每通必做）

即使卡上无 `promptScenes`，也注入结构化时间事实（给模型校正用语；不要求念给用户）：

```text
[用户本地时间]
- 现在：<iso 本地>，本地小时=<0–23>
- 问候与节奏应符合当前本地时间；勿说错「早上好」等。
- 与剧情冲突时：objective / forbidden 优先，时间事实仍保留。
```

- Free：`timeMentionPolicy = allow_casual`  
- Story：默认 `correct_only`

### 5.5 Opening LLM 上下文裁剪

首句如果走 LLM，不等于把完整通话上下文都交给模型。`OpeningLlmContextPolicy` 决定首句 LLM 消息如何投影：

| policy 字段 | 含义 |
|-------------|------|
| `includeSystemHard` | 保留 objective / forbidden / style / situation 等 hard 约束 |
| `includeSpeakable` | 保留可说上下文 |
| `includePrivate` | 保留私有剧情提示；仅 server/壳 LLM 可见 |
| `includeSoftContext` | 是否允许 softContext 总体进入首句 |
| `includeMemory` | 是否允许 `[memory]` 记忆块进入首句 |
| `includeInertia` | 是否允许 `[conversation.inertia]` 对话惯性进入首句 |

未知玩家呼入首句的安全裁剪：

```text
includeSystemHard=true
includeSpeakable=true
includePrivate=true
includeSoftContext=false
includeMemory=false
includeInertia=false
```

这样即使 Profile 里有用户姓名、长期记忆、上一通对话惯性，模型也不会在“喂，请问哪位？”之前看到这些内容。后续用户开口后，普通对话轮次才恢复 Memory / inertia 投影。

### 5.6 通话中过程事件（过程话术）

与挂机 Exit 的 `hangup_early` 不同：下列事件**不改 Profile**，只触发角色 `callFlowPrompts` 或 Adapter 注入下一轮。

| DialogueEvent | 选用 |
|---------------|------|
| `silence_timeout` | `callFlowPrompts.longSilence` |
| `call_duration_threshold` | `callFlowPrompts.longCallNudge` |
| `pre_hangup_hint` | `callFlowPrompts.preHangupFarewell` |

**计时归属（定稿）：**

| 角色 | 职责 |
|------|------|
| **壳 / DialogueAdapter** | 按策略计时并上报上述事件（Realtime 与 text_turn 均由 Adapter 负责） |
| **引擎** | 不计时；按 `callFlowPrompts.*` 取变体 → 注入下一轮或请 Adapter 播一句 |
| **Studio Manual** | 调试器按钮「模拟静默 / 长通话 / 预挂机」发同一事件即可 |

默认阈值（角色 `callFlowPolicy` 可覆盖，见 [11](./11-角色与社交.md)）：

| 项 | 默认 |
|----|------|
| `silenceTimeoutMs` | `15000` |
| `longCallNudgeMs` | `600000`（10 min） |
| `preHangupHintBeforeEndMs` | 壳在用户点挂机前可选上报 |

### 5.7 与老话机效果对照

| 老机制 | 本设计 |
|--------|--------|
| 呼入/呼出不同开场 | Opening Situation + 卡 `promptScenes` + 角色日常 default |
| 按时段切提示词 | `localHourRange` / `toneHint` / temporal opening（**禁止** `timeBuckets`） |
| 长静默 / 长通话话术 | Adapter 计时 + `callFlowPrompts` |
| 壳内 if 拼装 | Prompt Provider 固定管道 + Host first-turn gate |
| AI 有时间观念 | `ComposeScene.localTime` 强制注入 |
## 6. 与主链衔接

```text
（门面）Resolver → Composer → Host.consumeOpeningFirstTurn → adapter.start / 普通对话
  → events …（tool → RuntimeExitCandidate；过程话术事件）
  → session.ended
  → Story：OutcomeEvaluator → ExitSelector → Effect → save
  → Free：FreeCallPostPipeline（MemoryCommit；有候选则再 ExitSelector）→ save
```

Studio 文本调试典型 API：

```text
POST/SSE /api/debug/chat     # 用户一句 → server LLM → 引擎 → 流式回浏览器
POST     /api/debug/endCall  # 挂机推进
POST     /api/debug/simEvent # 模拟 silence_timeout 等
```

## 7. Studio 分档

| 档 | 行为 |
|----|------|
| v1 | Manual（电话事件 + beats）；可手动登记动态出口；可模拟过程事件 |
| v1.1 | server 侧 TextDialogueAdapter + 浏览器聊天 UI；首句先经 `consumeOpeningFirstTurn` |
| Outcome | 默认 Manual；高级「文本建议 Outcome」可改后再确认（见 [19 §13](../技术设计文档/19-引擎宿主与会话模型.md)） |
| Free 挂机 | FreeCallPostPipeline（见 [19 §5](../技术设计文档/19-引擎宿主与会话模型.md)） |
| 壳 | RealtimeDialogueAdapter（负责过程话术计时上报） |

`playback_only`：不开放聊天，只模拟播放完成/跳过。

### 7.1 隐私

author 可见 `privateBrief`；playtest 默认隐藏；导出日志不落 private 原文（见 [04](./04-调试器界面需求.md)）。

### 7.2 编辑期首通提示词预览

- 目的：在保存/调试前确认「首通」LLM 载荷形态；**不是**调试器通话。
- Studio V2：`POST /api/prompt-preview`（Server）复用 `composeRenderedPrompt` + Memory/Lore softExtras + `resolveToolPolicy` ∩ Registry；system 拼接与 TextDialogueAdapter 同口径。
- 不建 `CallSession`，因此只展示 `RenderedPrompt.openingFirstTurn` 的预览形态，不执行幂等消费；须 `userId`（UserGate / studioSession）；见 [03 §1.2](./03-编辑器界面需求.md)。

## 8. 工程约束

- 引擎：端口类型、Composer、ToolRegistry、会话钩子；零 React
- LLM/Realtime **SDK 仅 server 或壳**；禁止 `'use client'` 调厂商 API
- 禁止 client 在 tool 回调里写 Profile

## 9. 验收要点

- Manual / Text 都能走到 ExitSelector；Text 时 Key 仅在 server
- client 不 import 引擎写口
- 工具只登记候选、不直接改 Profile
- Composer：`ComposeScene` / `RenderedPrompt` / `openingFirstTurn` / `DialogueSessionSpec` schema 可测；方向/时段 layer 命中；每通注入用户本地时间；patch 不得覆盖 objective/forbidden
- Opening：玩家主动呼入 unknown caller 时 direct 首句不得包含用户姓名、记忆、对话惯性；预约/计划回电应能带回电话题
- Prompt Provider：`debug.providerIds` / matchedLayerIds 可观测；Studio/壳不得绕过 Host 自行拼首句
- 过程话术：Adapter 上报事件；引擎不计时；调试器可模拟三类事件
- 工具：Registry 含旧话机七支业务工具；挂机 FC 不进引擎
