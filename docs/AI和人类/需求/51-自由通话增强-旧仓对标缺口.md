相关：[00-文档索引](./00-文档索引.md) · [02-运行时协议](./02-运行时协议.md) · [11-角色与社交](./11-角色与社交.md) · [12-记忆模型](./12-记忆模型.md) · [50-对话与模型适配](./50-对话与模型适配.md) · [引擎小改和增强计划](../sudioV2.0版本/需求/引擎小改和增强计划.md) · [19-引擎宿主与会话模型](../技术设计文档/19-引擎宿主与会话模型.md) · [24-L1能力包](../技术设计文档/24-L1第一方能力包与流水线插槽.md) · [25-L2第三方SDK](../技术设计文档/25-L2第三方能力包与SDK.md)

**状态：** 需求 backlog（1.1+）；**非 v1 收口范围**。本文列出 doubaoSister 自由通话侧「体验增强」在本仓的缺口、**架构落点**与 **ScheduleCard 前置依赖**，供排期与评审「会不会破框」。

**工程扩展：** 增强项落在 realtime/background 插槽——先 [24 L1](../技术设计文档/24-L1第一方能力包与流水线插槽.md)（引擎 `capabilityPacks` 静态装配），对外用 [25 L2](../技术设计文档/25-L2第三方能力包与SDK.md)（workspace `plugins/<特性>/` + 清单三分；完整包装 API；不管私有存储；ACL 见 25§12）。禁止继续深耦进 Host 主链。执行勾选见 [L1 前置与分期索引](../里程碑/v2.0/L1能力包与插槽_前置与分期执行索引.md)。

## 1. 范围与排除

### 1.1 本文覆盖

- `packageId` / `chapterId = __free__` 的**自由通话**主路径及跨通增强（Memory、调度、过程话术、Prompt 投影等）。
- 对标旧话机「日常聊、主动找、记得住、像真人」，但**必须**走本仓 CallCard + Port + 管线模型重做。

### 1.2 明确排除（不由本文驱动）

| 排除项 | 本仓落点 |
|--------|----------|
| **初识流程**（打错电话、记名、第一次见面剧本） | **Story 包 + CallCard + Effect**（如 `wrong_number_act1`、`golden_handoff`）；Free 卡不得承载剧情 opening（见 [11 §4](./11-角色与社交.md)） |
| **初识门闩**（旧仓 `firstContactCompleted` 一类） | **不做**；可拨性用 `effectiveDialable = dialable \|\| unlocked`（见 [02 §3.2](./02-运行时协议.md)） |
| **暗号门闩 / Access Gate**（呼入识别 +  passphrase） | 若需要，放在 **Story 卡** 的 guard / opening，非 Free 通用能力 |
| **打错号码 + 语音信箱剧情** | Story 柱（已有 `wrong_number_act1` 等方向）；非 Free 缺口 |
| **旧仓迁移** | 对标能力，不迁代码 / Schema / store |

### 1.3 已等价 / 不在缺口单

- Reminder、Recurring schedule（引擎 tick + once/recurring intent，须绑 CallCard）
- Missed outbound 恢复（`missedOutboundAt` + Opening Situation）
- Secrets / Expert referral（Story + schedule 链）
- Bazi / Lore bootstrap（World 柱 + Studio server）
- **`[acquaintance]` 熟人辨认**（Profile 已有 `nickname` 时禁止再演记名；见引擎 `acquaintanceSoftExtra`）——属于 Free 日常，**不是**初识流程
- Free PostPipeline、MemoryCommit Orchestrator、Opening First-Turn Gate、conversation inertia 基础

## 2. 架构护栏（实现前必读）

以下与 [00 §4](./00-文档索引.md) 铁律一致；**任何 F 项不得绕开**。

| 护栏 | 要求 | 违反后果 |
|------|------|----------|
| **CallCard 驱动** | 每一通（含外呼/Idle）必须 `resolve → beginCall → frozenCard` | 回到旧仓「裸 topicHint 打电话」 |
| **通话中只登记** | 工具 → `RuntimeExitCandidate`；禁 direct Effect、禁 onConnect / 通话中写 Memory·Profile | 存档污染、调试/实机不一致 |
| **Free 挂机顺序** | `MemoryCommit →（有 candidate）ExitSelector → Effect` | 记忆与剧情状态乱序 |
| **LLM 不进引擎** | 抽取、Idle 选题、研究履约 → **Studio server / 壳**；引擎只交 `MemoryCommitInput` | 引擎纯度与 Vitest 边界破坏 |
| **Prompt 单管道** | 新上下文 = **Prompt Provider** 或 `promptScenes`；禁止 Studio/壳拼 system | 实机与 Studio 提示词分叉 |
| **真源三分** | Content JSON / 薄 Profile / Memory SQLite；Zustand **非**真源 | 「保存回滚」类缺陷 |
| **过程事件计时在 Adapter** | `silence_timeout` 等由 DialogueAdapter 上报；引擎 `selectCallFlowPrompt` | 引擎绑死 Realtime/text |
| **增强走 CapabilityPack 槽** | 新 Free 增强默认贡献 [24](../技术设计文档/24-L1第一方能力包与流水线插槽.md) 插槽；禁 beginCall/effect **中段**堆特性；禁引擎扫 workspace `plugins/` | Host 巨石、L2 无槽可挂 |

### 2.1 三条评审问题（每条 F 必填）

1. **生命周期**：本通 `CallSession`？跨通 `PlayerProfile`？长期 `Memory`？
2. **时机**：通话中 / 挂机 PostCallJob / 通间 `advanceClock`·schedule tick / server worker？
3. **入口**：能否经 **Tool→Candidate→Exit→Effect**、**PostCallJob**、**Prompt Provider**、**Effect+schedule** 表达？

若答案是「通话中扫 transcript 写档 / 无 card 外呼 / client 拼 prompt」→ **方案应拒绝或重写**。

## 4. ScheduleCard 前置依赖（F-01 / F-08 / F-22 硬前置）

> 定稿语义见 [引擎小改和增强计划](../sudioV2.0版本/需求/引擎小改和增强计划.md)。**在 ScheduleCard 与 recurring 绑卡完成前，不得实现「裸 Idle 外呼」。**

### 4.1 问题

旧仓 Idle / 周期外呼常是「topicHint + 直接拨号」。本仓铁律：**无 CallCard 则无通话**；`schedule_recurring_call` 缺卡引用应校验失败。

### 4.2 ScheduleCard 定义（目标形态）

| 项 | 定稿 |
|----|------|
| 类型 | `cardKind: "schedule"`；FreeCard **超集**（工具、interactionMode 继承） |
| 触发 | `Profile.schedule` tick → 物化 recurring/once → `agent_outbound` → resolve **ScheduleCard** |
| 会话 | `chapterId = __schedule__`（`SCHEDULE_CHAPTER_ID` 哨兵） |
| 与 Story 区分 | 剧情内「过几分钟让他打给你」= `schedule_call_card` 指向 **StoryCard**；周期日常 = **ScheduleCard** |
| Idle 选题 | 若用 LLM：在 **tick 物化 intent 时**（server）写入 `intent.topicHint`，再 `beginCall`；**禁止** beginCall 热路径调 LLM |

### 4.3 recurring intent 最小约束

- 必须含 `scheduleCardId`（推荐）或显式 `cardId`（Free/Schedule 快照）。
- 禁止仅 `topicHint` 的可执行 intent。
- tick 产出须可被 `resolve(agent_outbound)` 命中 pending。

### 4.4 与 F 项关系

| F 项 | 依赖 ScheduleCard |
|------|-------------------|
| F-01 Idle 兴趣外呼 | **硬依赖** |
| F-08 NPC 睡眠 / 外呼窗 | 部分依赖（defer 已有；周期外呼仍须绑卡） |
| F-22 生日/事件主动外呼 | **硬依赖**（once intent + 目标卡） |
| F-23 Idle 与 Cognition 污染隔离 | 随 F-01 |

### 4.5 前置验收（ScheduleCard 里程碑）

- [ ] `schedule_recurring_call` 缺卡引用 → `validatePackage` error
- [ ] recurring tick → `agent_outbound` → `beginCall.frozenCard.cardKind === "schedule"`
- [ ] Idle LLM 选题只写 intent，不 bypass resolve
- [ ] `effectiveDialable` 为 false 时外呼拒绝（无初识门闩）

## 6. 分项需求与落点明细

以下每项含：**旧仓意图**、**本仓做法**、**数据真源**、**时机**、**禁止**、**验收要点**。

### F-01 · Idle 兴趣话题主动外呼 · P0

| 维度 | 说明 |
|------|------|
| 旧仓意图 | NPC 根据兴趣/最近对话主动致电聊话题 |
| 本仓做法 | `schedule_recurring_call` 或专用 Idle intent → **ScheduleCard** → `agent_outbound`；话题写入 `intent.topicHint` 或卡 `context` |

| 时机 | schedule tick 物化；server 可选 LLM 选题 |
| 禁止 | 无 card outbound；beginCall 内 LLM；client 触发 Host |
| 验收 | tick → resolve → frozenCard=schedule；不可拨角色不外呼 |
